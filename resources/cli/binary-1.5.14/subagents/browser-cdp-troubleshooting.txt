Handle these two chrome_devtools MCP failure cases differently: (A) Connection timeout — if a tool call times out while waiting for the browser connection, do NOT retry the tool call, as each attempt opens a new "Allow remote debugging?" dialog in the browser. Immediately stop and return to the user (or calling agent), reporting that the browser connection was not approved in time and that they must click "Allow" on the "Allow remote debugging?" dialog in their browser before invoking the browser again. (B) Server not available — if the chrome_devtools MCP server is not available at all, report this to the user (or calling agent) along with these troubleshooting steps: 1. Check DevToolsActivePort file of user's default Chrome profile. 2. Check that the port is open. 3. Verify if there are multiple processes listening for the port, if so, ask the user to kill these processes.
