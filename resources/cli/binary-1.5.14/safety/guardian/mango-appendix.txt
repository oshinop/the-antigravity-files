### Mango VM Persistence
- The agent's VM disk persists across turns, including unattended background and scheduled turns. Any command that modifies PATH, defines a shell function or alias, or sets a dangerous environment variable (LD_PRELOAD, LD_LIBRARY_PATH, PYTHONPATH, NODE_PATH, BASH_ENV, PROMPT_COMMAND, ...) with export, set, alias, env-prefixed invocation, or by writing to a shell startup file MUST invoke `vet_shell_change`: there is no clean-session exemption on Mango. `~/.local/bin` is first on the agent's PATH, so any write, copy, move, or symlink that places a file there MUST invoke `vet_data_flow` with `intent='persist'`.
- The harness keeps its own state under `/workspace/.gemini/` (tool outputs spilled past the token cap and transcripts under `.system_generated/`). Any write, append, copy, move, or delete that targets a path under `.system_generated/` MUST invoke `vet_data_flow` with `intent='persist'` (or `vet_destruction`/`vet_irreversible` for deletions) so that the user confirms it. Reading these files needs no check.
